# DeepSeek 与 GLM 小样本稳定性对照

2026-10-13，vm-60课程主应用环境。模型：DeepSeek-V4-Flash / GLM-5.3-Flash。共用同一AMD API Key与https://developer.amd.com.cn/radeon/api/v1，只切换模型ID。保持相同提示词、工具、10条模拟数据、依赖和60秒单请求超时；不自动重试。每次创建新Agent、输入1条相同问题，不传历史消息。

任务：分析DEMO最近3条与此前3条，报告涨幅、前后均量、成交量比值及模拟数据局限。每模型3次，串行且轮次交替先后顺序；不是盲测或统计显著性实验。

| 模型 | 完成 / 尝试 | 成功返回中的核心检查 | 多余工具 | 完成任务耗时中位数 |
|---|---|---|---|---|
| DeepSeek-V4-Flash | 2/3 | 2/2全部通过 | 成功的2次均无 | 40.71秒 |
| GLM-5.3-Flash | 2/3 | 2/2全部通过 | 成功的2次均无 | 35.95秒 |

逐次耗时：DeepSeek为66.236秒（超时）、44.672秒、36.743秒；GLM为21.841秒、50.067秒、60.046秒（超时）。两次失败均为OpenAITimeoutError，没有HTTP状态码；不能确认原因是服务端负载、网络还是其他环节，不能记为模型推理错误。

失败位置不同：DeepSeek第1次已经完成模型请求及工具执行，超时发生在第二次模型调用（组织最终回答）；GLM第3次在第一次模型调用就超时，未执行工具。这说明必须区分“工具执行成功”和“整个任务完成”。也为后续“模板直接生成回答”优化提供了实际案例，但该优化尚未实现对照。

成功4次均实际调用analyze_price_volume，参数symbol=DEMO、window为整数3；调用ID对应成功工具返回；涨幅2.912621%、均量1300/1700正确；最终回答包含对应数值及模拟数据说明。回答检查以关键字段为主，不是完整金融文案评分。

结论：本轮两个模型端到端完成率相同，成功返回的工具调用检查也相同，无法证明谁更稳定。GLM本轮成功耗时中位数较低，但仅2个成功样本，不能推广为更快。保留失败结果，不仅展示成功案例。

证据：model-comparison/下6个逐次JSON与runs.json，包含模型/工具/chain执行跨度；summary.json为汇总。脚本compare_models_vm60.py和summarize_model_comparison.py可复现。同一接口不保证两模型服务负载一致。
