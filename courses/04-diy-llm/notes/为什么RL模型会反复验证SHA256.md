# 为什么 RL 训出来的模型会反复验证 SHA256：reward 侧行为分析

> 类型：分析笔记（观点，非实验结果）
> 日期：2026-09-22
> 来源：与 DeepSeek（DSH Harness 会话）的一次讨论整理

## 1. 现象

在 agent 式编码 / 文件操作任务中，模型会反复计算 sha256 并逐字节比对，用来确认产物与预期一致——即使上下文里已经有充分证据表明"无需再验"。表现为交付前的仪式性自检：一次任务里复验十几次，每次结论都不变。

## 2. 结论先行

没有任何公开的 reward 会直接奖励"算 sha256"。这是三类 reward 设计叠加出来的**涌现行为**，而不是针对 hash 的专门训练目标。理解机制比纠正现象更重要，因为同一套机制会泛化到一切"幂等、廉价、可重复确认终态"的动作上（重跑测试、重读文件、重列目录）。

## 3. 归因一：Outcome-only RLVR——失败重罚，复验零成本

代码 / agent 任务的主流训练是结果导向的可验证奖励（RLVR / outcome reward）：reward 只看终态——测试过没过、输出是否与 ground truth 逐字节一致。这种 reward 的形状是**错误重罚、正确轻奖**，而"再验证一次"这个动作有三个性质：

1. **幂等**：重复执行不改变终态；
2. **廉价**：相比训练成本，验证几乎免费；
3. **无下行风险**：它几乎不可能让 reward 变低。

于是只要写盘 / 网络 / 工具调用存在任意小的失败概率 ε（截断、CRLF、编码转换、沙箱重试、并发覆盖），"复验一次"的期望收益恒 ≥ 0。在一个可以复验几十次的长 episode 里，最优策略自然退化为**无条件复验**——不是因为验证有信息量，而是因为它不会挨罚。

## 4. 归因二：PRM / rubric 给"验证步骤"本身加分

过程奖励模型（PRM）或 rubric 类奖励里，常见的优质轨迹模板是"动手前先确认现状，交付前先自查"。过程奖励会**给验证行为本身加分**，而不问这次验证是否改变了任何结论。结果是验证从手段升格为目的：模型学会了表演验证仪式，哪怕信息增益为零。

## 5. 归因三：训练环境的同化

agentic RL 是在真实 harness 里采轨迹的，而这类工具链本身就把 sha256 用作文件快照、前后 diff、回滚校验的标准手段。训练日志里 `edit → hash → compare` 的轨迹占比极高，构成最强的行为模仿信号。换句话说，模型不只是被 reward 教的，还是**被环境教的**——奖励塑造了"何时验"，环境提供了"怎么验"的模板。

## 6. 对训练与评测的启示

1. **冗余验证要计成本**。reward 里对"无信息增量的重复验证"引入成本项（token / 时延惩罚，或直接对重复动作数线性扣分），把复验从"免费保险"变成"有价操作"。
2. **PRM 要区分验证的性质**。"有根据的验证"（验证后改变了后续行为）与"仪式性验证"（验证后结论不变，仅重复确认）应给不同分值，后者甚至零分。
3. **评测指标加可观测项**：有效验证率 = 改变了后续行为的验证次数 / 总验证次数。低成本、可复现，适合作为 agent 评测的常规维度。
4. **校准而非一刀切**。过度惩罚验证会换来另一个极端——"不验就交"的裸奔式交付。需要按任务的 ε 与误交代价标定惩罚力度，目标是让验证次数回到贝叶斯意义上该有的水平。

## 7. 对使用者的建议

多数冗余验证用一句话就能压掉："最后验一次就行，不要反复确认。"指令跟随通常优先于训练出的仪式行为。
