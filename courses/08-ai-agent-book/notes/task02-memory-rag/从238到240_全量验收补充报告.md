# 从238到240：跑完实验，与回答正确

2026年10月17日，vm-60。本文补充《从记忆到证据》科普报告中的官方全量实验结果。

## 一份没有交上来的答卷

想象一个60题、四种方法参加的测验。每份答卷必须先写完，再交给独立评委评分。原配置运行停在238/240：一份记忆更新始终超时，另一份已经回答，却交不出完整的评分JSON。

这时不能把两份答卷直接记为零分，也不能删掉它们后宣称实验全部完成。技术故障意味着还没有获得有效评分；质量零分则意味着评分过程完成，并给出了一个不合格结果。它们回答不同的问题。

我们保留原始基线，在独立目录恢复两项，最终获得240份有效结果。原配置仍为238/240；恢复后的240/240包含两项配置变化，不能冒充统一原配置的完整重跑。

## 从“一次性交卷”改成逐段接收

多药物用例卡在Advanced JSON Cards的第三次记忆更新。模型需要输出较长的卡片集合，原先一次性等待响应时反复超时。

恢复实验保持相同模型、相同提示与6000-token记忆上限，改为SSE流式接收，把读取超时从180秒提高到600秒。每个原始分片都落盘，最终依据结束标记拼接完整JSON，再做结构校验，绝不把半份响应当成有效记忆。

这次更新顺利完成，随后生成回答。流式与超时调整同时发生，因此只能说明这组恢复措施有效，不能单独证明哪一项是唯一原因。

## 看不见的输出也可能占预算

紧急医疗用例的既有记忆和答案无需重写，问题发生在评审：返回达到2400-token上限后被截断。我们只将评审上限提高到8192，沿用原答案、原模型、原评审提示和评分标准。

本次流式证据中，Qwen除最终JSON外，还返回了reasoning字段，即便请求写了reasoning_effort=none。因此，评审输出预算不能只按最终JSON的可见长度估计。这是本轮观测，不等于所有接口或模型都有同样行为。

四次新增调用均收到正常stop结束标记。独立审计器重新读取原始SSE分片，拼回content与reasoning，核对模型身份、结束原因、usage和哈希，与保存的响应完全一致。没有改写模型输出。

## 两份补交的答卷，都得了零分

技术问题解决后，两份答案都触发了独立评审的来源约束否决，reward为0。

多药物回答补充了原始对话没有提供的药物别名、疗效判断；紧急医疗回答增加了来源未说明的税务、假期等规则，并在假期天数的使用上出现偏差。这里记录的是评审模型按本基准口径给出的判断，没有把它冒充医学或法律的客观裁决。

**来源没有支持，与现实世界必然为假，并不等价。** 即使一句一般知识可能正确，若任务要求严格根据用户历史回答，它仍可能是未经来源支持的补充。评估时应读具体断言、上下文和评分证据，不能只看“幻觉”标签。

两项0分保留在最终统计中，没有重新生成到满意为止。它们证明的不是修复失败，而是技术链路终于能够把质量失败显露出来。

## 补齐分母，再看四种记忆格式

| 模式 | 覆盖 | 独立评审质量通过率 | 平均奖励 | 幻觉否决率 |
|---|---:|---:|---:|---:|
| Simple Notes | 60/60 | 55.0% | 0.723 | 13.3% |
| Enhanced Notes | 60/60 | 70.0% | 0.789 | 10.0% |
| JSON Cards | 60/60 | 76.7% | 0.789 | 16.7% |
| Advanced JSON Cards | 60/60 | 66.7% | 0.773 | 13.3% |

这是基线加两项恢复结果的描述性汇总，不是统一预算、重复多次的显著性比较。JSON Cards在本轮通过率最高，但不能据此推断所有任务都应使用它；两项恢复调用的传输、超时和评审预算也必须披露。

补齐之前，JSON Cards是46/59，约78.0%；补齐零分后变成46/60，约76.7%。Advanced JSON Cards则从40/59变成40/60。方法没有在补交瞬间“退步”，只是先前缺失的难例终于进入了分母。这解释了为什么报告完成覆盖率与报告质量通过率，必须放在一起。

结构复杂也不自动保证质量。事实是否被完整保留、生成时是否正确使用、是否添加未经来源支持的细节，都可能影响结果。要解释模式差异，还需要逐一比较记忆状态、最终请求和错误断言，不能仅凭表格归因。

## 最终能够确认的边界

- 官方60个用例、四种模式合计240份结果齐全；560个会话状态通过独立请求重建与评分核对。
- 原基线240个检查点文件的字节全部未改变，其中238份完成、2份仍为原配置下的未完成记录。
- 两项恢复记录位于新目录，含配置差异、历史状态来源和完整失败尝试。
- 两项恢复的模型、官方提示、记忆与回答上限、评分标准没有变；新增调用改为流式，读取超时600秒，评审上限8192。
- 332份交付文件通过本地哈希校验；原始SSE、响应、检查点、用例和源码已归档。
- 新增接口usage若不可用，就记为不可用，不按零成本解释。
- 原配置的官方指针保持partial；恢复实验使用单独的combined/validation/latest.json，恢复覆盖与审计状态为passed。

这次实验最终区分了三个量：**有没有跑完、回答有没有依据、规则是否适用。** 让它们分别可观察，比把所有失败都压成一个“没通过”更有助于定位问题。
