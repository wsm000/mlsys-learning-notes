# 3-5：按词查资料，分数怎样算出来？

## 机制目标

像查养蜂手册的关键词索引：先确定哪些资料出现了查询词，再按词的稀有程度、出现次数和资料长度评分。BM25本身不调用生成模型，也不会自动理解同义词。

本轮在vm-60运行从零实现：6条养蜂资料、显式空格分词、倒排索引、逐词BM25评分。用小语料是为了让每个数字都能追溯。分词边界由教学样例给定，未评测中文分词器。属于等价机制实验，不是官方原引擎全量验收。

## 一、分词：先约定怎样数词

原文：蜂群出现王台，需要检查分蜂征兆。

本例保留的分词结果：`蜂群 王台 分蜂 检查`。

这四个词才是检索器实际建立索引的输入。原文里有、分词结果里没有的词，本实现不会检索到。分词不是BM25自动解决的环节。

## 二、倒排索引：由词找到文档

```text
分蜂 → D1:1次，D2:2次
王台 → D1:1次，D2:1次，D5:1次
检查 → D1至D6：各1次
```

“倒排”表示从“文档包含哪些词”反过来，变成“一个词出现在哪些文档”。查询`分蜂 王台`时，取两个词对应文档的并集，候选只有D1、D2、D5，其他三条无需逐文档匹配。

这里采用OR召回，故只有“王台”的D5仍能入选；是否要求全部词命中，是检索策略的选择，不是BM25公式强制规定的。

## 三、BM25：稀有词更有区分力，重复词收益递减

本例使用正值IDF变体：

`IDF = ln(1 + (N-df+0.5)/(df+0.5))`

`词贡献 = IDF × tf×(k1+1)/(tf+k1×(1-b+b×文档长度/平均长度))`

- N=6；平均长度=29/6，约4.833词。
- tf：该词在当前文档出现几次。
- df：整个语料中有几篇文档出现该词，重复次数不改变df。
- k1=1.5控制词频饱和；b=0.75控制长度归一化。

“分蜂”只出现在2篇文档，IDF约1.030；“王台”出现在3篇，约0.693；“检查”6篇都有，仅约0.074。少见词更能帮助区分文档，常见词的贡献较低。

同样在平均长度下，tf从1、2、4增至8，对应词频因子为1.000、1.429、1.818、2.105。重复越多仍会加分，但不会翻倍增长。

固定tf=1，将长度从4增加到8、16，对应因子从1.084降至0.772、0.490。长度归一化减少长文档仅靠更多文字获得的优势；它不表示长文档必然不相关。

## 四、看真实排名与每一项分数

查询：`分蜂 王台`。

| 文档 | 分蜂贡献 | 王台贡献 | 总分 | 排名 |
|---|---:|---:|---:|---:|
| D2 | 1.455 | 0.683 | 2.137 | 1 |
| D1 | 1.116 | 0.751 | 1.868 | 2 |
| D5 | 0 | 0.683 | 0.683 | 3 |

D2“分蜂”出现两次，其收益超过了比D1稍长的长度惩罚。D5只有“王台”，仍有部分得分。分数是当前语料和参数下的排序信号，不是答案正确的概率。

对D1的“分蜂”贡献另写显式算式核对，独立计算与引擎均得到1.1162229195608817，误差0。这只核对该算例，不把它当作对所有输入的形式证明。

## 五、故意改一个词，看机制边界

| 查询 | 实际结果 | 原因 |
|---|---|---|
| 分蜂 王台 | D2、D1、D5 | 有词面匹配 |
| 分家 | 无候选 | 索引没有“分家”，不会自行关联“分蜂” |
| 分蜂 | D2、D1 | 人工改写为语料词后恢复命中 |

第三行是人工控制的查询改写，不宣称系统自行学会了同义词。它把问题定位在词面匹配阶段：尚未进入生成环节，也不是生成模型没有回答好。

这与3-4相接：此前向量检索可以把“蜂群准备分家”关联到“分蜂征兆”；BM25本例对完全无共享词的“分家”没有候选。语义表示与词面匹配各有所长；下一项3-6将让两路检索处理同一组问题，再融合、重排。
