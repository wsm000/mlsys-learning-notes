## 已有学习判断

- 存储聊天记录不代表新请求能使用这些信息，还需要读取并放进上下文。
- 回答碰巧用了生活化比喻不能独立证明记忆生效，需要查看写入记录和真实请求。
- “解释技术概念时先用养蜂作比喻”适合保存为长期教学偏好。
- “今天只有十分钟”是临时条件，本实验不写入长期偏好。
- 明确改成做饭比喻后，应更新当前有效偏好，旧记录可保留但标为失效。
- 相似度不代表新鲜度；新旧偏好都被检索到时，需要状态、时间或替代关系解决冲突。

## 实验边界与设计

本实验是参照本章记忆生命周期编写的最小教学实验，不是直接运行教材 user-memory 项目，也不是教材 3-1/3-2 的完整 60 用例评测。不能据此声称教材完整验收通过。

执行机器：vm-60。完整成功对照使用 AMD DeepSeek-V4-Flash；早期 DeepSeek-V4.1-Flash 尝试遇到共享模型并发满与超时。密钥从虚拟机已有文件读取，脚本与证据不含认证请求头。

1. 用真实模型从虚拟用户原话提取长期偏好，并核对来源引用、排除临时条件。
2. 保存 memory.json，用新 Python 进程执行不读取记忆的回答。
3. 再用一个新进程读磁盘中的 active 偏好，放入请求并回答相同问题。
4. 用真实模型提取“以后改用做饭”的纠正，旧偏好标记 superseded。
5. 新进程只读取有效的新偏好，再回答相同问题。

持久化、用户隔离、状态过滤由程序实现；偏好提取与回答由真实模型完成。当前只验证单用户流程，不代表多用户隔离经过独立测试。

## 如何判断

先看 memory-before-update.json 与 memory.json，再看各轮 *-read.json 和请求中的 messages，最后看真实模型回答。不同回答使用不同进程，旧聊天不传入问答请求。

checks.json 只验证程序机制；回答是否遵从偏好还需人工阅读。temperature=0 也不能保证跨请求绝对一致；单轮对照不能证明统计上的因果效果。

首轮执行出现 HTTP 429，必须保留失败记录。第二轮增加 35 秒调用间隔与最多三次尝试；最终结果以真实输出为准。
