# Task 2｜用户记忆和知识库

教程：深入理解AI Agent，Chapter 3：https://github.com/bojieli/ai-agent-book/tree/main/chapter3

学习日期：2026年10月15日。实验环境：vm-60、Python 3.10.12、AMD DeepSeek-V4-Flash。Embedding使用真实BAAI/bge-small-zh-v1.5，512维。

## 学习理解

用户记忆帮助助手在后续交互中使用用户偏好和已知事实。短期记忆主要体现为当前请求中的会话上下文；长期记忆由应用持久化，随后按用户和有效状态读取，再放入请求。存储成功、读取成功、模型遵从是三个不同环节。

用户纠正偏好后，可以将旧记录标记失效、保留历史，并将新偏好设为有效。相似度只表示相关性，不代表信息最新。临时计划应带有效期限，或仅留在当前上下文。

知识库提供回答所需的外部依据：文档切分为片段，用Embedding编码查询与片段，检索相关证据，再把证据交给模型生成回答。用户记忆关注个人事实与偏好，知识库关注外部知识；二者都可以使用检索。

## 实际实验与结果

1. **用户记忆闭环**：提取养蜂偏好并持久化；新进程读回后使用养蜂比喻；更新为做饭偏好后，旧记录失效、新回答采用做饭比喻。6项机制检查通过。只有虚拟单用户，不代表多用户隔离完成验收。
2. **RAG对照**：真实向量与关键词检索在本小样本文档命中率相同。60字分块命中正确文档却漏掉七轮重试证据，120字分块补齐；资料没有学生优惠时拒答。说明文档命中不等于证据完整。
3. **组合失败**：记忆偏好进入请求后，模型有一次未使用做饭比喻、漏引用，并把“不会立即丢弃”说成“不会丢”。保留真实失败，说明读到记忆不等于遵从，生成也可能夸大证据。
4. **跨章节例外**：仅相邻扩展找不到企业冻结例外；追加条件检索或人工规则关联后，正确给出“默认17天，企业冻结期间暂停清理”，并区分个人登录锁定。解冻后的计时规则未规定，模型没有编造期限。两种扩展的输入token分别增加约41%和60%。

第一轮条件实验出现跨题证据泄漏，已判为无效对照并保留；修正后确保同批题证据一致，解冻题单独调用。

## 我的故障排查框架

以下为学习过程中本人提出的三个核心问题：

1. 正确证据进最终上下文了吗？
2. 相关记忆是否过期、是否与证据冲突、是否被注入？
3. 模型输出到底依赖了哪一条？引用支持结论吗？

补充边界：引用可以核查断言支持性，但不能直接证明模型内部依赖关系。需要时通过移除、替换证据或记忆做对照；本轮尚未实施系统性的因果归因实验。资料、偏好和系统指令也应分清，避免将检索文本当作执行指令；本轮未开展提示注入攻击测试。
