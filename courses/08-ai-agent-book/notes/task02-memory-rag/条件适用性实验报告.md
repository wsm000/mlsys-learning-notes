# 跨章节例外：引用支持与条件适用性

本实验延续Task2的Memory/RAG基础教学，实际执行于vm-60。资料为虚构星舟笔记政策，不是真实产品规则；不是教材完整基准验收。

## 设计

默认17天规则位于回收站章节，企业冻结期间暂停清理位于企业治理章节，个人登录锁定位于安全章节。例外不与默认规则放在同一篇文档，因此同源相邻扩展不能直接补齐它。

使用已有BAAI/bge-small-zh-v1.5真实512维向量、80字块、20字重叠、Top-3；仅检索当前2026版、active、public资料。按同文档、同版本与同访问范围扩展相邻块。生成模型固定为AMD DeepSeek-V4-Flash，提示相同。

三组：

1. neighbors：向量Top-3，再取同源±1相邻块。
2. condition-search：第一组再追加一次条件/例外检索，Top-3及相邻块并入上下文。
3. linked-rules：从第一组命中文档沿人工编写的一跳规则关联补取完整关联文档。

追加查询包含企业冻结、个人登录锁定、解除冻结和重新计时等人工选定关键词。因此它是已知业务范围内的模板检索，不是模型自主发现未知例外。规则关联同样是人工编写，不是自动知识图谱抽取。两种方案均带有额外业务知识，不能把收益解释为纯粹增加上下文的效果。

## 修正过的对照问题

第一轮conditional-rag-20261015-01把五题及不同证据放在同一个请求里。模型在冻结题引用了只提供给解冻题的governance片段；该轮发生跨题证据泄漏，不能计入有效对照，已停止并保留文件。

第二轮conditional-rag-20261015-02对前四题做了程序断言：同组每题提供的chunk_id集合完全一致，题间不会多出隐藏例外。解冻题单独调用，不与其他题共享上下文。所有生成组使用新请求，不带上一组回答。

## 实际结果

| 情形 | 仅相邻扩展 | 追加例外检索 / 规则关联 |
|---|---|---|
| 账户状态未知 | 回答默认17天；unknowns承认例外未知，正文未给冻结例外 | 回答默认17天，同时给出企业冻结暂停清理，无需先追问 |
| 普通个人账户 | 给默认17天，但因缺少条件资料而较保守 | 应用默认17天，没有套用企业冻结 |
| 企业账户被冻结 | 承认不知道冻结是否影响清理，不能完成条件判断 | 明确冻结期间不执行到期清理，并指出解冻计时未规定 |
| 个人登录被锁定 | 不知道锁定是否影响清理 | 区分登录锁定与企业冻结，仍应用默认规则 |

仅相邻扩展确实取回了17天规则，引用ID也存在，但它不能提供跨章节例外。这是证据完整性不足，不应把保守的不确定回答一律记为幻觉。

三组为前四题提供的证据分别为4/6/7块，原始字符数293/425/478。追加检索比基线增加约45%的证据字符，规则关联增加约63%；这些是扩展块原文长度之和，含重叠，不是token数或完整请求长度。新增上下文与检索成本需要权衡，不能只比较回答质量。

服务端实际记录的三组批量请求输入token分别为1842、2598、2950，比基线分别增加约41%和60%。这是四题共用请求但重复提供每题证据的总输入，包含消息格式与元数据。单次观测不构成稳定性能基准；generation文件中的seconds包含人为调用间隔等待，不能直接当成模型纯推理延迟。

独立解冻题实际输出：“解除冻结后如何重新计时，资料未规定，不能推断保留期会重新计算为17天或立即删除。”其引用来自提供的governance片段，未编造新期限。

规则关联仅执行一跳；从retention到governance再到login-lock的第二跳未自动展开。因此它不是完整性证明，也不能保证找到所有未知例外。

## 指标边界

metrics.json保存人工标注目标文档的覆盖率，但locked用例预设了三个目标文档，而governance本身已经写明个人登录锁定不属于企业冻结。这导致取回retention和governance虽只有2/3文档覆盖，仍可能支持正确条件判断。因此文档覆盖率不是语义充分性评分，下一版标注应允许等价证据集合，不能事后修改本轮标签来提高分数。

程序只检查claims中引用非空、ID属于该题提供片段；报告中的事实与适用性结论由人工阅读核对，没有独立LLM裁判，也不声称大规模泛化效果。

模型将applies_if统一输出为true。这个字段不能表示具体适用条件，说明提示与schema还不够严格：后续应明确要求结构化的账户类型、冻结状态及条件来源，不能把该布尔值当作适用性验证通过。

## 学到什么

回答需要分别检查：来源是否支持断言、规则是否适用于当前用户、是否遗漏会改变结论的规则。条件不完整时，补检索优先于编造；资料足够但用户状态未知时，默认规则加明确例外可避免不必要追问。
