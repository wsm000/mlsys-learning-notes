# 3-12：知识散落在案例里，怎样整理成可复用的模式？

## 本实验想实现什么机制？

像整理一批巡蜂记录：原来只有一段段描述，先发现值得记录的因素，再提取成统一表格，把相似记录聚成案例类型，最后对没参与建模的新记录做匹配。

```text
训练案例原文
    ↓ 模型发现候选因素
明确字段定义和数据类型
    ↓ 逐例结构化提取
特征表 → 训练集内拟合缩放与聚类 → 原型及记录统计
                                      ↓
留出案例 → 相同字段提取 → 匹配原型 → 有范围限制的说明
```

这与前面的RAG不同：不只是把已有文档找出来，而是从许多案例中建立新的结构和统计摘要。统计关联仍不等于因果规律。

## 实际输入与训练／留出分离

vm-60，30条虚构训练案例、9条留出案例。训练记录包含观察、登记处置、后续记录；6条留出记录有登记类别用于事后对照，另外3条为混合情况或信息缺失，没有指定正确处置类别。

观察中有不同气温、饲料、通风及蜂螨描述。训练动作和结果由实验作者按模板设计，不是真实养蜂资料，不能据此推荐实际处理方式或证明效果。

本地Qwen3-0.6B只看训练观察发现因素，再逐例提取。留出观察没有参与因素发现、缺失值拟合、缩放器、KMeans、决策树或原型统计；留出登记标签只在最后对照，没有输入提取或说明模型。

这是替代官方CAIL2018法律案例的大规模流程的等价机制实验，不是官方原样复现。

## 一、模型发现了哪些因素？

模型真实输出了五项：

| 字段名 | 模型给出的条件描述 |
|---|---|
| 气温 | 7摄氏度 |
| 蜂群活动 | 偏少 |
| 饲料储备 | 不足 |
| 通风 | 正常 |
| 蜂螨 | 未发现 |

这是候选schema，不是已经合格的知识表示。“气温=7摄氏度”过于具体，也没有正确使用要求的英文键名。温度更适合保留数值，或采用有清晰依据的区间定义；不能把一个样本值直接当作一般因素。

## 二、提取为表格后，错误也可能变整齐

本轮将每项条件编码为1（存在）、0（明确不存在）、-1（无法判断）。模型对39条记录分别生成向量，并保存原始响应。

出现12条格式失败；训练特征中70个值未知，留出特征中21个值未知。另有可解析但内容错误的向量，例如：

```text
原文：气温8摄氏度，蜂群活动偏少，饲料不足，通风正常，未发现蜂螨迹象。
模型向量：[1, 0, 1, 1, -1]
```

若严格按其自身定义，8℃不等于7℃；“活动偏少”明明出现，却被标成0；“未发现蜂螨”也没有按条件读出。**JSON正确不等于字段提取正确。**

## 三、聚类形成了什么？

原流水线用训练中位数填补未知值，再标准化、运行KMeans，得到3簇，并汇总各簇的登记处置和后续记录。决策树另学习这些特征对“登记处置类别”的预测关系，输出特征重要性。

本例预设最多3簇，不是算法自行证明案例天然只有3类。

看起来三簇很整齐，但部分组来自共同的提取失败和填充值，而不是可靠的案例属性。特征重要性也只是在这张错误特征表和作者设计标签上的预测作用，不能解释成真实因果权重。

## 四、留出案例暴露问题

原流水线对6条有登记类别的留出案例，原型常见类别仅匹配2条。更值得注意的是V009：原文没有温度、饲料、通风和蜂螨结果，模型5项都未知；填补后它恰好等于某个簇中心，距离显示0。

```text
信息全缺失 → 填成训练中位数 → 与簇中心相同 → 距离0
```

**距离0证明数字相同，不证明证据充分。** 不能把缺失信息经填补得到的近邻，解释为高度可靠的案例匹配。模型生成的说明还把新案例缺失信息误说成整个训练簇都缺失，原文及统计都需核对。

## 五、受控修订：先把字段含义做清楚

保留上述失败结果，另做人工明确schema与规则提取的对照：

| 字段 | 类型与来源规则 |
|---|---|
| temperature_c | 直接提取原文摄氏温度，连续数值 |
| food_shortage | 明示不足=1，明示充足=0，否则缺失 |
| poor_ventilation | 明示不足=1，明示正常=0，否则缺失 |
| mite_present | 明示发现=1，明示未发现=0，否则缺失；先处理否定词 |

这是实验作者的字段修订与确定性提取，不是模型自动学会了正确schema。同时改变字段定义与提取器，不能据此孤立比较“规则模型谁更强”。

再按同样的训练／留出分离方式做缩放、聚类、原型统计：

- 6条常规模板留出记录，都匹配到相同的登记类别。
- 2条混合记录的距离超过设定的教学阈值，标为偏离训练模式。
- V009保留缺失状态，拒绝把它填成一个看似精确的匹配。

阈值为训练簇内距离95分位数与0.5中的较大者，只是示意规则，没有经过真实分布校准。模板数据本来就很容易分开，6/6不能当成真实泛化、处理有效性或安全性的证明。

## 六、案例原型能支持什么结论？

可以说：“这条观察最接近训练簇2；该簇有10条记录，其中某种登记处置最常见。”

不能直接说：“这种处置导致恢复，遇到同类情况必须这样处理。”训练数据中的措施、后续情况和其他因素可能共同变化；本轮还是作者设计的数据，更没有证明现实因果。

原型的作用是组织已见案例、解释相似性与暴露缺口。新组合、缺失字段、来源不可靠或相似性不足时，应保留不确定性，不能强行套类型。

## 十二项的最后一条连接

前面实验主要问“怎样保存和找回已有知识”；3-12进一步问“怎样从案例中形成结构”。两者最后仍回到同一个检查：字段从哪里来、转换有没有改意、统计支持到哪一步、当前案例是否适用。
